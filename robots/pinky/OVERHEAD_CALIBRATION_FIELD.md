# 전체 카메라 네 기준점 현장 캘리

2026-10-27. 현재 카메라 구도와 1920×1080을 유지한다. 로봇팔 상단을 보이게 다시 배치하지 않는다. P1 한 대를 손으로 옮겨 기록하며, RViz·초기 위치 추정·주행 명령은 사용하지 않는다.

## 바닥 기준점 표시

기존 맵은 가로 200cm × 깊이 150cm다. 아래 거리는 카메라 영상의 테두리가 아니라 **실제 맵 바닥 경계**에서 잰다.

- 왼쪽: A 구역 쪽의 바깥 경계. B/C 사이 칸막이가 아니다.
- 대기쪽: 로봇팔 구역의 반대편, 두 대기자리와 가까운 맵 아래쪽 경계.
- 두 거리를 줄자로 재서 교차점에 테이프 십자를 붙인다. 기준점은 로봇팔 작업대 밖 통로에 있다.

| 번호 | 위치 | 왼쪽 경계에서 | 대기쪽 경계에서 | layout x/y (m), 자동 입력 |
| --- | --- | --- | --- | --- |
| 1 | 통로 A쪽 | 30cm | 65cm | 0.30, -0.85 |
| 2 | 통로 C쪽 | 170cm | 65cm | 1.70, -0.85 |
| 3 | 대기구간 A쪽 | 30cm | 20cm | 0.30, -1.30 |
| 4 | 대기구간 C쪽 | 170cm | 20cm | 1.70, -1.30 |

이는 새로 제안한 기준점 위치다. 실제로 표시·측정했다고 간주하지 않는다. 현장 장애물이나 가림으로 표시점에 놓을 수 없으면 좌표와 실제 위치를 함께 바꾼다. 원래 번호를 누른 채 다른 위치에서 기록하지 않는다.

P1의 **상단 마커 중심이 십자 바로 위**에 오게 놓는다. 작은 추를 단 실이나 수직 레이저로 바닥 수직점을 맞출 수 있다. 바퀴·바구니 모서리를 기준으로 맞추지 않는다. 로봇 앞방향은 자유이며 상단 마커 면 높이 **143mm**를 유지한다.

## 실행

카메라를 쓰는 기존 영상 프로그램은 Q로 닫는다. 관제 노트북에서:

```bash
cd /home/noma/dev_ws/kernel-robot-repo-3
bash scripts/run_pinky_overhead.sh calibrate \
  --dictionary DICT_5X5_1000 --marker-id 0 --plane-height-mm 143 \
  --anchors-file config/pinky-overhead-anchors.example.json
```

1. P1 마커 중심을 바닥 **1번** 십자 위에 놓는다.
2. **영상 창을 클릭해 키보드 포커스를 주고 숫자 1**을 누른다. 검출된 마커 중심과 기존 공용 지도 변환의 기준 좌표가 자동 선택되고 영상이 고정된다.
3. **영상 창 Enter**로 저장한다. 터미널의 `대응점 저장`을 확인한다. 이 방식에서는 M/X·지도 클릭·좌표 수동 입력이 필요 없다.
4. P1을 **2번**에 놓고 영상 창 `2 → Enter`, 이어 **3번**에서 `3 → Enter`, **4번**에서 `4 → Enter`를 수행한다.
5. 네 점 기록 후 영상 창 **S**로 캘리를 저장한다. 터미널에 `saved`와 등록점 오차가 나오면 **Q**로 종료한다.

같은 번호를 다시 기록하면 해당 대응점만 갱신한다. 중간에 R은 선택 해제, U는 마지막 대응점 삭제다. 작업이 끊겼으면 같은 명령에 `--resume`을 붙여 이어간다.

기준점과 실제 map 좌표를 읽기만 하려면:

```bash
bash scripts/run_pinky_overhead.sh anchors \
  --anchors-file config/pinky-overhead-anchors.example.json
```

## 네 점 저장 후 별도 한 점 확인

등록점 사이 중앙을 검증점으로 쓸 수 있다. 왼쪽 경계에서 **100cm**, 대기쪽 경계에서 **42.5cm**, layout 좌표는 **1.0, -1.075m**다. 바닥 표시와 마커 중심을 맞춘 뒤:

```bash
bash scripts/run_pinky_overhead.sh check --dictionary DICT_5X5_1000 --marker-id 0
```

영상 창 **M → X**, 터미널에 `1.0 -1.075` 입력 후 Enter, 다시 영상 창 Enter로 검증 결과를 저장한다. Q로 종료한다. 실제로 검증점을 표시한 경우에만 이 좌표를 사용한다.

## 결과와 다음 작업

- `runtime/field/pinky-overhead/points-draft.json`: 네 기준점 번호·영상 중심·layout/map 좌표.
- 같은 폴더의 `point-01.jpg`~`point-04.jpg`: 기준 사진.
- `calibration.json`: 143mm 평면의 영상→지도 변환, 등록점 오차와 별도 검증 기록.

이번 단계는 카메라 좌표 등록이다. 주행 위치 보정은 아직 연결하지 않는다. 기존 대기 목표 네 개와 A/B/C 주차 목표는 유지한다. 이후 두 로봇의 지도 위치를 확인하고 저장해 둔 대기 목표와 연결한 뒤, 실제 ROS 위치추정 반영으로 이어간다.
