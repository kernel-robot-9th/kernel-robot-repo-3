# Pinky 카메라 위치 보정·관제 전체 시연 남은 작업

갱신: 2026-10-27. 현재 우선순위와 완료 여부는 이 문서를 기준으로 한다.

**큰 마커 검출 → 부착·카메라 위치 확정 → 전체 카메라 좌표 등록 → 주행 위치 보정 → 관제 전체 시나리오·두 대 시험 → 대기장소 정밀주차·충전(후순위).**

전체 카메라를 다시 사용하는 첫 목적은 주행 중 흔들리는 지도 위치추정의 보완이다. 대기장소 정밀주차·충전은 이 구성을 재사용할 후속 과제이며, 앞 단계의 완료 조건에 넣지 않는다.

## 2. 역할과 유지할 설정

| 구성 | 역할 |
| --- | --- |
| 관제 전체 카메라 | 두 로봇의 큰 상단 마커를 지도 좌표로 변환해 주행 위치추정 보완 |
| A/B/C 구역 카메라 | 기존 적재·하역 지점의 마지막 정밀주차 |
| Route Server | 정해 둔 경로 그래프에서 경로 계산 |
| Nav2 제어기 | 경로 추종·실제 이동. Route Server만으로 위치추정 흔들림이 해결되는 것은 아님 |
| 관제 | 주문·로봇 배정·작업 인계·공용 구간 사용 순서·완료·복귀 |
| 향후 충전대 | 기존 대기자리 한 곳에 자석식 USB-C 케이블과 폼 지그 설치 검토 |

- 공용 지도, 기존 실측 변환, A/B/C 위치, 두 대기자리와 고정 경로를 재사용한다.
- A/B의 OMX 설정·자세·캘리·그리퍼 값을 보존하고 서로 복사하지 않는다.
- 마커 교체로 영향을 받는 영상 주차 등록만 갱신한다. OMX 자세 재측정은 하지 않는다.
- 마우스로 찍은 앞방향을 정답으로 취급하지 않는다. 마커의 지정 변과 실제 차체 앞방향 관계를 사용한다.
- 실제 설치·등록·주행은 단계별 승인 범위에서 수행한다. 추가 중단 조건이나 무관한 전체 시험을 붙이지 않는다.
- 명령·동작 종료, 좌표 등록, 실제 주차·적재·하역 성공을 구분해 기록한다.

## 3. 순서별 작업

### 1단계 — 큰 마커 검출 확인

- [ ] 검출 시험용 큰 마커를 출력한다. 출발 후보는 **검은 정사각형 80mm + 사방 흰 여백 10mm = 전체 100×100mm**이며 최종 확정값은 아니다.
- [ ] 관제 카메라를 실제 사용할 USB 연장선으로 연결하고 1920×1080 MJPEG 영상을 확인한다. 장치 지원 최대 모드는 30fps이며 실제 수신 fps는 화면에서 확인한다.
- [ ] 맵의 가까운 곳·먼 곳·양끝·대기자리와 A/B/C 진입부에 후보 마커를 분포시켜 검출 개수와 영상상 크기를 비교한다.
- [ ] 최종적으로 로봇 상단과 같은 높이에서 방향을 바꿔 검출되는지 확인한다. 바닥 종이 검출만으로 상단 마커 검출 성공이라고 하지 않는다.
- [ ] 원본 영상·표시 영상·검출 결과를 저장해 크기와 카메라 구도를 선택한다.

관제 노트북에서 실행:

```bash
cd /home/noma/dev_ws/kernel-robot-repo-3
bash scripts/run_pinky_marker_view.sh
```

화면의 마커 개수·ID·짧은 변 픽셀 길이·fps를 본다. `S`로 저장, `Q` 또는 Esc로 종료한다. 자료는 `runtime/field/pinky-marker-view/`에 남긴다.

완료 근거: 실제 설치 후보 구도에서 필요한 위치의 검출 화면. 이 단계에서 카메라 위치·마커 크기를 확정하지 못하면 좌표 등록으로 넘어가지 않는다.

### 2단계 — 마커 부착·카메라 설치 위치 확정

- [ ] 두 로봇을 구별할 ID를 정한다. 권장 후보는 같은 사전의 P1=0, P2=1이다. 현재 둘 다 ID 0이므로 아직 적용된 상태가 아니다.
- [ ] 마커 판을 차체에 대해 고정하고 실제 검은 변 길이·바닥부터 마커 면 높이·차체 중심 오프셋·앞방향을 기록한다.
- [ ] 레이더 위 판의 부착 가능 여부는 실제 구조에서 확인한다. 센서 옆면을 가리지 않는다는 이유만으로 고정 가능하거나 회전에 영향이 없다고 단정하지 않는다.
- [ ] 벽 쪽 카메라 위치와 각도를 고정한다. 기존 제안인 바닥 기준 렌즈 높이 약 2m는 시험 시작 후보이며, 검출 결과로 최종 높이를 정한다.
- [ ] 향후 충전대로 쓸 기존 대기자리 한 곳을 화면에서 잘 볼 수 있게 배치한다. 이 단계에서는 충전 정밀주차를 개발하지 않는다.

완료 근거: 부착 사진, 로봇별 마커 정보, 고정된 카메라 높이·방향·해상도 기록.

### 3단계 — 전체 카메라와 공용 지도 좌표 등록

- [ ] 기존 도구와 저장 형식을 재사용한다: [전체 카메라 도구](OVERHEAD_CAMERA.md).
- [ ] 렌즈 왜곡 보정 자료를 확인하고 영상→지도 변환 방식을 확정한다.
- [ ] 기존 실측 지도 좌표를 기준으로 넓게 분포한 대응점을 등록한다. 흔들리는 AMCL 현재값을 정답으로 삼지 않는다.
- [ ] 바닥 평면과 상단 마커 평면의 높이 차이를 반영한다. 같은 높이의 기준점을 사용하거나 카메라 자세와 높이로 보정한다.
- [ ] 마커 지정 변에서 로봇 앞방향을 계산한다. 기존 도구의 앞방향 클릭 입력은 이 단계에서 마커 기준 입력으로 보완한다.
- [ ] 등록에 쓰지 않은 위치에서 P1/P2의 지도 위치·방향 오차를 기록한다. 대기자리 쪽 오차도 남겨 향후 충전 검토에 재사용한다.

완료 근거: 캘리 파일·로봇별 정보·별도 검증점 오차 기록. 화면상 위치 표시만으로 주행 보정 완료라고 하지 않는다.

### 4단계 — 카메라 위치를 주행에 반영

- [ ] 설치된 AMCL·odom·TF 구성에서 카메라 관측을 어디에 결합할지 확인하고 최소 변경안을 확정한다.
- [ ] 카메라 관측에 로봇 ID·지도 좌표·방향·촬영 시각·관측 오차 정보를 담아 각 로봇에 전달한다.
- [ ] 기존 `odom → base`를 유지하고 `map → odom` 발행 주체를 하나로 구성한다. 구체적인 필터·설정은 현재 ROS 구성 확인 후 결정한다.
- [ ] 카메라 미검출 구간에서는 기존 위치추정을 이어간다. 매 영상 프레임마다 초기 위치를 다시 찍는 방식으로 연결하지 않는다.
- [ ] P1 한 대의 기존 경로에서 보정 전후 위치·방향과 실제 주행을 비교한 뒤 P2에도 적용한다.
- [ ] 관제 화면에 로봇별 카메라 관측·추정 위치·관측 시각을 연결한다.

완료 근거: 카메라 관측이 실제 Nav2 위치추정에 반영된 기록과 주행 결과. 그래프 경로 계산 성공과 실제 경로 추종 성공도 구분한다.

### 5단계 — 관제 설정과 전체 시나리오 시험

큰 마커 교체에 따른 **기존 A/B/C 정밀주차의 복구·등록 갱신은 이 단계의 인계 준비**다. 마지막 단계로 미루는 것은 대기장소의 새 정밀주차·충전 기능이다.

- [ ] 새 크기·ID·높이·앞방향을 A/B/C의 해당 로봇 geometry에 반영하고, 바뀐 목표 영상·후진 관측을 필요한 조합만 다시 등록한다.
- [ ] 새 마커 기준 관측 지점까지 Route Server 이동→기존 구역 주차→팔 실행 인계를 확인한다.
- [ ] A의 재기록한 슬롯 0 접근 자세로 실제 적재를 확인한다. 기존 YOLO 튜닝을 다시 시작하지 않는다.
- [ ] B 적재와 C 카메라·모델·실행 경로를 확인한다. C의 미반영 실행기 수정도 함께 확인한다.
- [ ] 관제에서 **새 주문 → 적재 → 이동 → C 하역 → 대기 복귀·완료**를 먼저 한 대로 성공시킨다.
- [ ] 두 대의 로봇 배정·두 대기자리·공용 구간 사용 순서와 복귀를 확인한다.
- [ ] 사용자가 계획한 주문 6개와 두 대 운용을 실행하고 결과를 기록한다. 실제 시험 전 주문 구성과 물량은 현장 조건에 맞춘다.
- [ ] 관리자·고객 화면의 상태가 실제 작업과 이어지는지 확인하고 최종 관제 화면과 전체 시연 영상을 확보한다.

완료 근거: 주문 ID와 상태 이력, 로봇별 주행·주차·팔 실행 기록, 사용자 실물 확인, 시연 영상. 이전 실패 주문을 되살리는 작업은 하지 않는다.

### 6단계 — 대기장소 정밀주차·충전, 시간 여유가 있을 때

**현재 보류. 5단계 완료 후 별도 계획·승인으로 착수한다.**

- [ ] 전체 카메라만으로 선택한 대기자리의 위치·방향 오차를 측정하고 주차 목표를 등록한다.
- [ ] 기존 구역 주차의 관측→odom 접근을 재사용할 수 있는지 검토한다.
- [ ] 자석식 USB-C 케이블과 폼 지그의 접촉 위치·방향을 정하고 반복 도킹을 확인한다.
- [ ] 실제 충전 상태를 확인할 신호를 정한다. 주차 도달·자석 접촉·실제 충전 시작을 별개 결과로 기록한다.
- [ ] 확인된 경우에만 관제의 충전 상태·복귀 후 충전 절차로 연결한다.

## 4. 기존 현장 성과·자료

- P2/A 정밀주차 성공 기록: `runtime/field/pinky-parking/runs/20261027-122118-P2-A-align-7b912d/`.
- P1 출발부는 실제 추정 위치에서 고정 출차 경로로 연결하도록 수정했고, 이후 사용자가 A 진입 성공을 확인했다.
- A/P1 마커 관측 부족으로 해당 후진 관측 목표만 3cm 더 안쪽으로 조정했다. 관련 자료: `runtime/field/pinky-route-review/A-P1-inward3cm-20261027-151127/`.
- A 슬롯 0 접근 재기록 준비·백업: A 노트북의 `runtime/field/a-slot0-approach-reteach-20261027-152014/`.
- 기존 작업 명령: [두 대 현장 명령](TWO_ROBOT_FIELD_COMMANDS.md), [구역 주차 방식](ODOM_PARKING.md).
