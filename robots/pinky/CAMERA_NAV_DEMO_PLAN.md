### 추가 시험: 관제 주문 기반 v3 두 대 출차·합류

- **목적:** 전열 로봇의 출차·회전·경로 연결 시간이 후열보다 길 때, 뒤차가 먼저 합류하거나 앞차를 따라잡아 서로 간섭하는지 확인한다. 고정 경로·한 대씩의 성공만으로 두 대 동시 주행 성공을 판단하지 않는다.
- **입력:** 사용자 주문 화면에서 A 구역 상품 3개+B 구역 상품 3개, **총 6개 품목을 주문**하고 관리자 화면으로 배차·작업 상태를 확인한다. 이는 별도 최종 시연의 ‘주문 6개’와 구분한다. 실제로 두 대에 어떻게 나뉘어 배차되는지도 시험에서 확인한다.
- **실행 경로:** 터미널에서 두 로봇에 개별 이동 명령을 보내는 재현 대신, 관제의 실제 주문→배차→이동 명령 흐름으로 실행한다. 두 대 모두 v3 선택을 확인한다.

- **방법 B:** 적재·하역 준비 전에 주행만 먼저 시험한다. 실제 로봇 이동·주차와 관제 배차 흐름을 사용하고 팔 동작만 생략한다. 작업 완료 인계 방식은 구현 현황을 먼저 확인해 별도 준비한다. C VLA·카메라·팔 실행은 호출하지 않는다. 작업 시간을 모두 0초로 생략하면 실제 출발·재출발 순서와 달라질 수 있으므로, 실제 작업 대기 및 늦은 전열/빠른 후열 조건도 구분해 재현한다.

<summary>v3/v4 경로 기준</summary>

### 주행 경로의 기준

- `replay-1.html`은 **v3 기본 순환 경로**, `replay.html`은 **v4 작업대 간 단축 경로**다.
- 초기 검토는 `replay.html`의 v4로 진행했으나, 비교 시험 후 사용자는 **v3를 시연 경로로 선택**했다. 바닥 도로도 실제 v3 동선을 참고했다. 관리자 기본값이 자동으로 v3로 바뀌었다는 뜻은 아니며 주문 시연 전 선택값을 확인한다.
- 현장에서는 출발 연결·실측 주차·관측 깊이·대기 진출입을 수정했으므로, 원본 재생과 현재 실행 경로가 모든 점에서 같다고 가정하지 않는다.
- 새 선택 기능은 두 로봇 공통으로 설정하며 **다음 고객 시작부터 적용**한다. 기존 고객은 시작 시 버전을 유지한다.
- 두 버전은 동일 Route Server 그래프 안에 서로 다른 노드 ID로 준비했다. 배포 후 선택 때마다 서버를 재시작하지 않는다.
- A/B/C 정밀주차·적재·하역·대기 정렬은 공통이다. 경로별 두 대의 이동 순서와 실제 충돌 여부는 각각 시험한다.

<summary>보류한 전체 카메라 재캘리 검토안</summary>

### 전체 카메라 재캘리 — 보류

현재 캘리·주행 보정·대기 정밀주차 설정을 유지한다. 아래 내용은 재개할 때의 검토 자료이며 즉시 수행할 작업이 아니다.

### 현재 오차와 원인 구분

- 사용 중인 `runtime/field/pinky-overhead/navigation-calibration.json`: 기존 기준점에 대한 잔차 RMS **61.5mm**, 최대 **80.5mm**, 계산에 쓰지 않은 별도 검증점 오차 **67.3mm**다. 맵 전체의 최대 실측 오차를 뜻하지 않는다.
- 이전 수동 네 점 캘리 `calibration.json`의 별도 검증점 오차는 **82.9mm**다. 네 점 자체에 거의 정확히 맞았다는 이유만으로 실제 위치가 정확한 것은 아니다.
- 실제 외곽을 정확한 2m×1.5m 직사각형으로 가정해 기준 좌표를 부여했다면 오차가 생길 수 있다. 외곽이 찌그러져 있어도 내부에 정확한 기준 좌표를 만들면 캘리할 수 있다.
- 현재 파일에는 렌즈 왜곡 보정이 적용되지 않았다. 자동 주행 자료에는 odom 미끄러짐·접촉 영향도 있어, 현재 오차를 바닥 외곽 하나의 문제로 단정하지 않는다.

### 보존한 현장 기준 — 캘리에는 미반영

- 도로 **테이프 바깥쪽 끝 사이** 실측: 102×31cm. 사용자 지시로 직각으로 간주하고 추가 대각선 측정은 요구하지 않는다.
- 테이프는 대략 재단했다. 폭을 1cm로 가정하거나 중심선·안쪽 경계 기준으로 치수를 바꾸지 않는다. 재개 시 바깥 변의 기준선을 잡아 네 교점을 사용한다.
- 직사각형 로컬 좌표 후보: `(0,0)`, `(1.02,0)`, `(1.02,0.31)`, `(0,0.31)`m. 아직 ROS map 원점·방향에 연결한 좌표가 아니다.
- 사진: `runtime/field/road-marking-photos/20261028-153711-road-102x31.jpg` (1920×1080).
- 이전 100cm 길이·60cm 간격 평행선 제안은 적용하지 않는다. 새 후보의 정확도는 별도 검증 전까지 미확인이다.

### 재개할 때의 좌표 계산·주행 반영 순서 — 현재 보류·미적용

1. 카메라 위치·해상도를 유지하고 기준점 영상 좌표와 실측 좌표를 대응시킨다. RViz 마우스 클릭이나 AMCL 추정값을 실측 정답으로 사용하지 않는다.
2. **바닥 높이 0mm와 상단 마커 높이 143mm를 구분한다.** 현재 주행용 변환은 143mm 평면 기준이므로 바닥 점을 여기에 그대로 섞거나 바닥 변환을 상단 마커에 그대로 적용하지 않는다.
3. 바닥 기준을 이용할 때는 카메라 내부 파라미터·왜곡과 자세를 구해 143mm 평면의 위치를 계산하는 방안을 검토한다. 별도 방법으로 기준점을 143mm 높이에서 수직 정렬해 기록할 수도 있다. 적용 방식은 코드 변경 전에 확정한다.
4. 새 실측 좌표계의 원점·방향을 기존 ROS `map` 좌표계와 연결한다. 내부 직사각형을 정확히 만드는 것만으로 기존 지도·경로·목적지의 좌표가 자동으로 맞는 것은 아니다.
5. 기존 캘리 파일은 보존하고 후보 파일을 만든다. 기준점 적합 잔차와 **계산에서 제외한 검증점 오차**를 별도로 기록해 기존 67.3mm 결과와 비교한다. 개선 폭이나 최종 정확도는 미리 보장하지 않는다.
6. 개선 확인 후 주행 보정에 적용한다. 대기 목표 네 개는 보존된 원본 마커 픽셀에서 새 변환으로 다시 산출하고, 기존 ROS 좌표를 유지했는지 확인한다. 구역별 A/B/C 카메라 정밀주차를 일괄 재등록하지 않는다.
7. 대기 복귀와 출차를 한 대씩 확인한 뒤 전체 시연 순서로 돌아간다. 카메라 연속 검출을 새로운 주행 중단 조건으로 추가하지 않는다.
