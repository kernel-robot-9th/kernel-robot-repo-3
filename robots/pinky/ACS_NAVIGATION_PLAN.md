# ACS 주행·교통 관리 적용 계획

갱신: **2026-10-30** · **분석·문서 준비 / 구현·실물 적용 미착수**

## 요약

- **착수 순서:** [C YOLO 하역](../omx_yolo_unload/README.md) → 전체 주문 시연·촬영 → [Three.js 실제 관제 연결](WEB_DIGITAL_TWIN_PLAN.md) → ACS 비교·실물 적용.
- **목표:** Pinky 두 대가 서로의 진행·구역 점유를 보고 출발·대기를 조절하고, 처리 시간·대기 시간을 기존 방식과 비교한다.
- **권장 첫 적용:** 검증된 v3 경로 + ACS 교통 관리. 참고 프로젝트의 A* 자유 경로는 다음 선택지로 둔다.
- **중요:** 이 권장 방식과 단계는 설계안이다. 이번 승인은 문서 작성이며 주행 규칙 변경·배포·장비 시험은 포함하지 않는다.

참고 프로젝트는 MOCK이다. 실시간 화면과 비교 시뮬레이션의 구역 해제 규칙도 같지 않으며,
내장 v3 비교 데이터는 현재 현장의 v3 동시 주행 성능을 대표하지 않는다.
3cm·±1.5초, 좌표 잔차 2cm, 10회 반복 등의 문서 수치를 현장 중단 조건이나 필수 시험 횟수로 그대로 도입하지 않는다.

## 기존 관제 재사용

- `server/order_fleet.py`: 주문 1건·상품 6개의 로봇별 작업 배정.
- `robot_gateway/hardware/control_fleet.py`: 선두/후열 상태, 선두 `home_depart` 통과 후 후열 출발, 구역 이동·정밀주차 연결.
- `robot_gateway/hardware/pinky.py`: Route Server·Nav2 경로 실행, 구간 결과·주행 기록.
- 전체 카메라·Nav2 map 위치와 기존 map/layout 변환, 로봇별 ROS 도메인.
- A/B/C와 대기장소의 검증된 정밀주차 동작 및 저장 목표.

주문 배정, 공용 통로 사용, 구역 점유를 서로 다른 계층이 중복 결정하지 않게 한다.
브라우저는 관제 서버의 판단을 표시하고, 실제 예약·출발 결정은 기존 관제 실행 흐름에 모은다.

## 단계별 체크리스트

### 1. 실제 상태와 비교 기록

- [ ] Three.js에서 두 로봇 실제 위치·방향·현재 구간·목적지·점유 상태 표시.
- [ ] 같은 주문 조건의 v3 실제 기록과 ACS 예측을 같은 시각 기준으로 비교.
- [ ] 배치·주차 목표·바구니 치수는 현재 현장 설정에서 읽기. 참고 `layout.json`을 덮어쓰지 않고 실제 설정과 대응.
- [ ] 기존 계산용 바구니 70%와 화면 실측 크기 표시를 구분. ACS 외곽 계산값은 실물 적용 계획에서 명시.

### 2. v3 경로 위 ACS 판단 — 관찰·기록

- [ ] 경로 구간에 예상 도달 시각을 붙이고 실제 진행에 맞춰 갱신.
- [ ] 어느 로봇 때문에 어느 구간에서 기다리는지, 언제 출발할 수 있는지 표시.
- [ ] 구역을 벗어나는 실제 진행과 바구니 외곽을 기준으로 점유 해제 시점 검토. 출발 명령 접수만으로 해제하지 않음.
- [ ] 두 로봇이 정지하거나 느려질 때 예약 예측이 달라지는지 기록.
- [ ] 관찰 단계에서는 ACS가 실물 명령을 변경하지 않도록 구성.

### 3. 실물 적용

- [ ] 기존 v3 / v3+ACS 모드를 관제에서 선택할 수 있게 연결. 운행 중 모드 변경의 적용 시점은 작업 시작 기준으로 정리.
- [ ] 출발·대기·재개를 기존 게이트웨이 명령에 연결하고 실제 진행으로 예약 갱신.
- [ ] 최소 시험: 한 대 경로 인계 확인 후 두 대의 전열 출차·후열 합류·C 순차 인계 확인.
- [ ] 기존 방식과 완료 시간·대기 시간·동시 주행 구간·실제 궤적을 비교해 채택 판단.

ACS의 예약 판단·대기 규칙은 필요한 기능으로 명시해 구현 계획에 포함한다. 임의 고정 지연이나 추가 정지 조건을 숨겨 넣지 않는다.

### 4. A* 경로 교체 — 후속 선택

- [ ] 도로를 유지할지 자유 경로를 허용할지 사용자가 결정.
- [ ] A* 결과가 현재 맵·바구니·주차 진입과 맞는지 3D에서 먼저 비교.
- [ ] 채택하면 순수 경로/예약 계산을 관제 Python 쪽으로 이식하는 안을 우선 검토하고, 기존 Nav2 `FollowPath` 실행부를 재사용.
- [ ] A*를 켰다는 이유로 정밀주차 실행기까지 새로 만들지 않음.

## 구현 전 확정할 결정

1. 첫 적용은 **v3+ACS** 권장. A* 자유 경로까지 동시에 바꿀지는 별도 결정.
2. 실제 진행 보고 주기와 예약 여유는 기존 실행 기록을 참고해 정한다. MOCK 속도 가정을 실측값으로 쓰지 않는다.
3. 이족보행 로봇의 통로 점유·양보 장면은 기본 두 대 시연 후 확장.
