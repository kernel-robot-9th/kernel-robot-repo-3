## 남은 작업

### 범위와 영향

기존 커밋 메시지를 바꾸면 해당 커밋과 후손의 SHA가 바뀐다. 코드 파일 내용은 그대로 유지할 수 있지만, 관제·A·B가 공통으로 사용하던 `91eee22` 같은 기준 SHA는 새 값으로 대응시켜야 한다. 기존 PR·외부 링크·팀원 브랜치에 기록된 SHA는 자동으로 모두 교체되지 않는다.

**권장 시점은 전체 시연 완료 후, 또는 팀원이 push하지 않는 별도 합의 시간이다.** 지금 현장 시험 중인 체크아웃에서 이력을 재작성하지 않는다. 새 커밋의 한국어 작성은 바로 적용할 수 있다.

재작성 제안 범위는 최종 원격 `main`에 포함된 전체 선조 커밋(병합된 가지 포함)이다. 원격의 별도 작업 브랜치와 태그까지 바꿀지는 팀원 작업 여부를 확인한 뒤 별도로 확정한다. 이는 과거의 코드 이력 통합을 다시 하는 작업이 아니라 메시지 변경이다.

### 실제 실행 절차 — 별도 승인 후 진행

1. 변경 대상 브랜치·태그, 위 제목·본문 번역, 팀원 push 중단 시간, 원격 강제 갱신 범위를 확정한다.
2. 최신 원격 이력을 별도 clone으로 확보하고 모든 refs의 bundle과 이전 SHA 목록을 로컬에 보관한다. 각 장비의 미커밋·ignored 현장 자료는 별도 백업한다.
3. 별도 clone에서 메시지만 바꾸는 방식으로 리허설한다. 작성자·작성 시각·커밋 순서·병합 부모 관계를 보존한다. 서명된 커밋이 있으면 기존 서명은 재사용할 수 없음을 확인한다.
4. 변경 전후 SHA 대응표를 저장하고 각 커밋의 tree가 같고 부모 관계가 대응하는지 확인한다. 파일 변경 없이 메시지만 바뀌었는지 검증한다.
5. 리허설 결과와 변경할 refs를 사용자에게 보여 준 뒤 이력 재작성·원격 반영을 승인받는다. 현재 문서 작성 승인은 이 단계의 승인이 아니다.
6. 승인된 refs만 확인한 이전 SHA를 명시한 `--force-with-lease`로 갱신한다. 원격이 그 사이 바뀌면 덮어쓰지 않고 대상 이력을 다시 맞춘다. 무차별 `--mirror` push는 하지 않는다.
7. 관제·A·B·C의 체크아웃을 새 이력에 맞춘다. 장비별 설정·모델·자세를 보존하고 이전/새 SHA 대응표를 남긴다. 이전 브랜치를 그대로 merge해 영어 이력이 되살아나지 않도록 팀에 전환 방법을 공유한다.

이력 변경 전까지도 포트폴리오 문서·새 커밋·PR 제목은 한국어로 정리할 수 있다. 과거 이력 번역 때문에 현재 전체 시연 준비를 멈추지 않는다.
