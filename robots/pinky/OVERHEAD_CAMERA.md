# 관제 전체 카메라 캘리와 Pinky 위치 표시 — 1단계

> **2026-10-27 최신 순서:** 큰 마커 검출·설치 확정 후 좌표를 등록하고 실제 주행 위치 보정에 연결한다. 아래 도구는 좌표 표시·기록 단계이며 ROS 위치 보정 완료 상태가 아니다. 전체 순서와 완료 여부는 [남은 작업표](CAMERA_NAV_DEMO_PLAN.md)를 따른다.

대기자리 두 곳 × 두 로봇의 목표를 먼저 남기는 명령은 [대기 목표 기록](WAIT_TARGET_RECORDING.md)에 있다. 캘리 전에도 영상 목표를 저장할 수 있다. `robot` 모드의 `--marker-id`·`--front-angle-deg` 옵션을 사용하면 앞방향 마우스 클릭을 생략할 수 있다.

현재 현장용 **줄자 거리표와 1~4 번호 선택 캘리**는 [네 기준점 현장 절차](OVERHEAD_CALIBRATION_FIELD.md)를 따른다. 공통 마커 면 높이는 143mm다.

이 도구는 **관제 Ubuntu 노트북**에서 실행한다. ROS 연결·주행·팔 동작은 없다.
전체 카메라 위치 보정용이며 A/B/C 구역 카메라의 정밀주차 목표·OMX 캘리는 바꾸지 않는다.

```bash
cd /home/noma/dev_ws/kernel-robot-repo-3
bash scripts/run_pinky_overhead.sh view
```

왼쪽은 관제 카메라, 오른쪽은 저장 지도다. 주황선은 기존 실측 배치의 지도 변환이다.
최초에는 마커 ID만 표시하고 캘리 후 지도 위치를, 로봇 등록 후 앞방향과 차체 위치를 표시한다.
카메라를 다른 프로그램이 사용 중이면 해당 영상 프로그램에서 녹화를 종료한 뒤 실행한다.
서버·worker·Nav2를 재시작할 필요는 없다.

2026-10-27 도구 준비 시 `/dev/video4`는 기존 ffmpeg(PID 449639)의
`runtime/field/pinky-first-a-20261026-172632/overview.mp4` 녹화가 사용하고 있었다.
그 녹화는 이번 도구 작성 중 종료하지 않았다. 관제의 overview 프레임 API도 당시 수신 프레임이 없었다.
따라서 현재 영상·마커 검출·실물 캘리 확인은 아직 완료하지 않았다.

## 1. 현재 카메라와 마커 확인

- 화면의 `DICT_...:ID`와 터미널의 검출 목록을 확인한다. Tab으로 선택 마커가 바뀌고 초록색으로 표시된다.
- 실제 P1/P2와 ID를 대응한다. 두 로봇은 구별 가능한 마커를 사용한다.
- Q로 종료한다. 여러 사전이 같은 마커를 검출하면 실제 인쇄한 사전을 `--dictionary DICT_...`로 지정한다.
- 설정은 `runtime/field/pinky-overhead.json`이 있으면 그 파일, 없으면 `config/pinky-overhead.example.json`을 읽는다.
- 현재 현장 설정과 기본 예시는 SNAP U2의 고정 by-id 경로, MJPEG 1920×1080, 요청 30fps다. 실제 처리 fps는 검출량에 따라 달라진다.

## 2. 상단 높이 평면의 영상·지도 캘리

필요한 실측값: 바닥부터 상단 마커까지 높이(mm).
**바닥 모서리나 벽 꼭짓점의 영상을 그대로 상단 마커 평면의 대응점으로 쓰지 않는다.**
같은 상단 높이의 기준점을 사용하고, 기준점 바로 아래 수직 투영 위치의 실제 지도 좌표를 입력한다.
예를 들어 Pinky 마커 중심 바로 아래의 위치를 기존 실측 배치에서 확인한 후 그 마커 중심을 기록한다.
차체 원점과 마커 중심이 다르면 차체 원점 좌표를 그대로 기준 좌표로 넣지 않는다.
기준점은 좁은 곳·일직선에 몰리지 않게 주행 영역에 넓게 배치한다. 최소 4점이며 추가 점도 사용할 수 있다.

아래 `<상단높이mm>`는 실제 측정 숫자로 바꾼다.

```bash
bash scripts/run_pinky_overhead.sh calibrate --plane-height-mm <상단높이mm>
```

각 기준점에서:

1. 기준점의 영상 위치를 클릭한다. 선택 마커 중심을 쓰려면 Tab으로 고른 뒤 **M**을 누른다. 영상이 고정된다.
2. **X**를 누르고 관제 터미널에 실제 `layout x y` 두 숫자를 미터 단위로 입력한다. 기존 공용 지도 변환이 자동 적용된다.
3. 이미 정확한 ROS map 좌표를 안다면 **Y**로 `map x y`를 입력한다. 또는 오른쪽 지도에서 대응 위치를 클릭할 수 있다.
4. OpenCV 영상 창으로 돌아와 **Enter**를 누르면 해당 점과 사진이 저장되고 실시간 영상으로 돌아간다.
5. 다음 기준점에서 반복한다. **U**는 마지막 점 삭제, **R**은 현재 선택 해제다.
6. 모두 기록한 뒤 **S**로 평면 변환을 저장한다. **Q**로 종료한다.

기존 실측 배치의 기준 좌표는 다음 명령으로 조회한다. 이 목록 자체가 카메라 캘리 완료를 뜻하지 않는다.

```bash
bash scripts/run_pinky_overhead.sh anchors
```

중단한 대응점 기록을 이어가려면 같은 카메라·해상도·상단 높이 상태에서 `--resume`을 추가한다.
영상 각도·위치·해상도·렌즈 설정이 달라지면 새로 등록한다. 두 로봇의 상단 높이가 다르면
`--calibration runtime/field/pinky-overhead/calibration-P2.json`처럼 평면 파일을 구분한다.

## 3. 별도 위치에서 오차 확인

```bash
bash scripts/run_pinky_overhead.sh check
```

등록에 쓰지 않은 실제 위치에서 위와 같이 영상점/M → X 또는 Y로 실제 좌표 입력 → 영상 창 Enter를 실행한다.
터미널과 캘리 파일에 x/y 오차 및 거리 오차(m)가 저장된다. 정답 좌표는 실측 배치를 사용하고 AMCL 현재값을 정답으로 쓰지 않는다.
등록점 4개의 적합 오차가 거의 0이어도 실제 정확도 보장은 아니다. 별도 위치의 오차로 판단한다.

## 4. 로봇별 크기·앞방향·차체 중심 등록

실제 검은 정사각형 한 변과 상단 높이를 mm로 입력한다. 흰 여백은 한 변 길이에 포함하지 않는다.

```bash
bash scripts/run_pinky_overhead.sh robot --robot P1 --size-mm <마커한변mm> --height-mm <상단높이mm> \
  --marker-forward-mm <차체원점에서마커중심까지전방mm> --marker-left-mm <좌측mm>
```

- Tab으로 P1 마커를 고른다.
- 마커 중심에서 보았을 때 **실제 로봇 앞쪽 방향의 먼 점**을 영상에서 클릭한다.
- Enter로 저장한다. P2도 `--robot P2`로 반복한다.
- 전방·좌측 거리는 부호가 있다. 뒤쪽·오른쪽이면 음수다. 정확히 원점 위에 붙였다고 확인한 경우만 0을 입력한다.
- 두 거리 옵션을 생략하면 마커 위치·앞방향만 등록한다. 차체 중심은 미등록으로 표시하며 임의로 같다고 처리하지 않는다.

다시 `view`를 실행하면 등록한 로봇 이름·지도 위치·방향을 볼 수 있다.
`latest.json`의 `base_pose`가 실제 차체 원점 위치다. 마커 높이가 현재 캘리 평면과 다르거나 중심 관계가 미등록이면 `base_pose`는 비워 둔다.
마커 실측 크기와 영상 변환으로 계산된 크기도 저장하므로 스케일을 비교할 수 있다.

## 렌즈 보정

이 카메라에 맞는 렌즈 보정 자료가 확인되지 않았다. 기본은 미적용이며 화면에 `lens:not calibrated`가 표시된다.
기존 자료가 있으면 별도 설정 파일의 `intrinsics_file`에 ROS camera_info 형식의 JSON/YAML 경로를 지정한다.
필드: `image_width`, `image_height`, `camera_matrix.data`(9개), `distortion_coefficients.data`.
자료는 같은 카메라·촬영 모드의 pinhole 모델이어야 한다. 다른 OMX 카메라의 캘리를 가져오지 않는다.
렌즈 보정을 추가/변경하면 같은 보정 영상 기준으로 대응점을 다시 등록한다.
렌즈 자료가 없으면 평면 변환만 적용한 상태로 별도 위치 오차를 기록하며, 실측 정확도는 확인 전까지 미확인이다.

## 저장 파일

모두 `runtime/field/pinky-overhead/` 아래에 저장한다.

| 파일 | 내용 |
| --- | --- |
| `calibration.json` | 영상→지도 행렬, 상단 평면 높이, 입력 대응점, 등록점 오차, 별도 검증 결과 |
| `points-draft.json`, `point-*.jpg` | 등록 중인 대응점과 해당 사진 |
| `robots.json`, `P1/P2-reference.jpg` | 로봇별 마커 크기·높이·중심 관계·앞방향과 참고 사진 |
| `latest.json` | 최근 검출 목록과 지도 위치, 관측 시각 |
| `latest.jpg` | 영상·지도 합성 화면 |
| `observations-*.jsonl` | 해당 실행의 검출·위치 기록 |

캘리 저장은 주행 보정 적용이 아니다. 실제 ROS 위치추정 연결은 전체 작업표 3단계다.
1단계 완료는 실제 캘리 파일·두 마커 등록·별도 위치 오차 확인까지 끝났을 때 기록한다.
