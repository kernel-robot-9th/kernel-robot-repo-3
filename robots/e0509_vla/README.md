# E0509 상품 집기 (SmolVLA + 카메라 보조) · 키오스크 · 디지털 트윈

Doosan **E0509** + ROBOTIS **RH-P12-RN(A)** 그리퍼가 작업대 위 상품(새우깡·초코송이·컵라면)을 집어 바구니(X350·Y-500)에 담는다.
키오스크(버튼·음성) 주문 → 상품별 집기·재시도 → RViz 디지털 트윈에 상태·경고·원인 표시.

- 정책: 상품별 **SmolVLA** (LeRobot, 15,000스텝). 내려가기·닫기 시점·운반·놓기를 정책이 정한다
- 카메라 보조: 위 카메라로 물건 위치를 재서 집는 위치를 맞춘다(정책이 정한 위치가 빗나가는 것을 보정)
- 안전: 경로 사전검사(IK·조작성), 작업영역·바구니 보호 구역, 실패 시 위로만 빠지기

## 성공률 (2026-10-22)

키오스크 주문, 칸 7곳(1·2·4·5·6·7·8번) × 상품 3종, 상품 23개 → **23개 모두 한 번에 집어 바구니에 넣음** (기록상 22/23, 1건은 확인 카메라 오인).
평균 소요(찾기~놓기 확인): 컵라면 70초 · 새우깡 77초 · 초코송이 87초.

## 구성

| 폴더 | 내용 |
|---|---|
| `vla/` | 실행·수집·학습 스크립트 |
| `kiosk/` | 키오스크 화면 (가격·총액·음성 주문) |
| `twin/` | 디지털 트윈 노드(RViz), 상품 3D 모델, 그리퍼 모델 |
| `tools/` | 티칭·복구·그리퍼 힘 시험 도구, 두산 공식 드라이버 패치 |
| `ros2_pkg/dsr_study/` | 그리퍼 ROS2 패키지(`dsr_gripper`, 컨트롤러 DRL 경유 RS485) |

### `vla/` 주요 파일

| 파일 | 역할 |
|---|---|
| `vla_run.py` | 한 번 집기: 카메라로 위치 → 정책 실행(내려가기·닫기·운반·놓기) → 놓은 뒤 카메라로 적재 확인 |
| `pick_loop.py` | 재시도 흐름(최대 3번): 실패 원인별로 정리 → 다시 찾기 |
| `kiosk_server.py` | 키오스크 서버(127.0.0.1:8765). 주문을 상품별 `pick_loop` 로 실행, 쉬는 동안 카메라로 트윈 동기화 |
| `infer_server.py` / `infer_worker.py` | 상품별 모델 3개를 GPU 에 올려 두는 상주 추론 서버 |
| `collect.py` | 자동 시연 수집(칸·무작위 위치), LeRobot 포맷 변환은 `convert_collect.py` |
| `failure_analysis.py` | 시도 기록으로 실패 원인 추정(위치 오차·빈손·미끄러짐·힘 부족·낙하 시점 등) |
| `bag_vision.py` · `choco_vision.py` · `ramen_vision.py` | 상품별 카메라 인식, `cam_*_pix2xy.json` 은 픽셀→작업대 좌표 보정식 |
| `fk.py` · `path_check.py` · `random_area_check.py` | 기구학·경로 사전검사, 안전하게 집을 수 있는 영역 계산 |
| `measure_report.py` | 성공률·소요 시간 자동 집계 |
| `demo_drop.sh` | 시나리오용: 지정 상품을 첫 시도에서 일부러 떨어뜨려 트윈 경고·재시도를 보여 줌 |
| `start_all.sh` | 드라이버·그리퍼·키오스크·트윈·RViz·추론 서버 한 번에 켜기 |

## 실행 (Ubuntu 24.04, ROS 2 Jazzy)

경로는 실행 PC(OMEN) 기준 `~/doosan_ws/vla_test` 에 맞춰져 있다. 다른 PC 에서는 각 파일의 절대 경로를 바꿔야 한다.

```bash
# 두산 드라이버(doosan-robot2, jazzy) 받은 뒤 tools/doosan-robot2.patch 적용, ros2_pkg/dsr_study 를 src 에 두고 colcon build
bash ~/doosan_ws/vla_test/start_all.sh        # 전체 켜기 -> 키오스크 http://localhost:8765
```

- 컨트롤러 `110.120.1.59:12345`, 네임스페이스 `dsr01`, `ROS_DOMAIN_ID=77`
- 학습: `train_overnight.sh <데이터셋>` (LeRobot `lerobot-train`, SmolVLA)
- 모델·데이터셋은 Git 에 넣지 않는다 (Hugging Face `sage0316/e0509_*`)

## 실기에서 배운 것 (반복하지 말 것)

- 그리퍼 서비스 `success=True` 는 완료가 아니다. 상태 읽기로 동작 끝을 기다린다
- 그리퍼 상태 읽기를 계속 켜 두면 컨트롤러가 과부하로 응답 불능 → 작업 중에만 켠다
- 놓쳤거나 미끄러지면 **다시 내려가지 않는다**. 위로만 빠지고 멈춘다
- 바구니 위에서 출발하는 경로는 높이를 유지한 채 시작 자세로 먼저 빠진다 (바구니를 끈 사고)
- 납작해진 새우깡 봉지는 그리퍼 값으로 쥔 것과 빈손이 구분되지 않는다 → 들어 올린 직후 카메라로 판정
- 바구니 바로 위는 특이점 구역이라 목표 몇 mm 앞에서 멈출 수 있다 → 도착 판정에 여유
- 드라이버의 공구 힘·외부 토크·관절 토크는 실기에서 0 만 나온다 → 접촉 감지는 카메라로
