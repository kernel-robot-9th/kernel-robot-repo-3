## 권장 구조

현재 작업에는 목표 조건을 받는 ACT와 결정적 작업 상태기의 결합을 첫 기준으로 권장한다.
최적이라는 결론은 실제 성공률·지연·시연 비용을 비교한 뒤 확정한다.
OMX1 8종과 OMX2 1종의 상품을 단일 정책으로 다루되,
정책의 단위는 `카트의 지정 상품 한 개 → 지정 바구니 → 안전 대기 자세`다.
주문 전체의 주행과 4개 상품 처리 순서를 신경망에 맡기지 않는다.

관제는 주문 ID, 중복 방지 요청 ID, 핑키 ID, 개별 물체 ID 목록,
각 물체의 SKU와 목표 바구니를 전달한다. 동일 SKU 여러 개도 물체 ID는 다르다.
사용자 확정: 핑키1의 상품은 왼쪽 바구니, 핑키2의 상품은 오른쪽 바구니로 옮긴다.
왼쪽/오른쪽은 기존 맵 기준으로 각각 x=1.29m / x=1.91m 바구니를 뜻하도록
설정하며, 실물 설치 시 같은 물리 바구니인지 확인한다. 로봇 자체 좌표의 좌우와 혼동하지 않는다.
관제가 핑키 ID에서 목표 바구니를 결정하고, 정책에는 그 바구니의 one-hot 목표값을 공급한다.
두 핑키가 동시에 도착하면 OMX3 작업권을 하나만 부여하고 나머지는 대기시킨다.

상태: 대기 → 요청 검증 → 도킹 및 핑키 정지 확인 → 상품 관측 →
단일 상품 정책 실행 → 집기/투입 결과 확인 → 다음 상품 → 완료 응답.
핑키는 완료 또는 명시적 취소·안전 복귀 확인까지 출발하지 않는다.
중복 요청은 기존 작업 상태를 반환하며, 새 작업으로 다시 집지 않는다.
시간 초과, 오래된 영상, 관절 상태 단절, 도킹 이탈 때는 실행을 중단하고 관제로 보고한다.
팔 동작 완료만으로 투입 성공 처리하지 않는다. 바구니 내부 물체와 카트의 감소를 확인한다.
관제 요청/상태 관리 노드를 구현했다. 도킹 센서 및 영상 성공 판정은 별도 연동 대상이다.
실행 방법은 `docs/OMX3_HANDOVER_INTERFACE_KO.md`를 참고한다.

## 먼저 작업 난도를 줄이는 방법

카트에 최대 4개를 서로 겹치지 않는 위치에 적재하도록 OMX1·2 적재 규칙을 맞춘다.
현재 카트는 12.5×15.4cm이므로 상품 4개가 실제로 분리 배치 가능한지 치수로 확인해야 한다.
가이드/칸막이를 추가한다면 집게 접근 공간도 확인한다. 현 카트 모델은 변경하지 않았다.
OMX3 도킹 위치와 방향을 고정하고, 카트 전체와 두 바구니를 보는 고정 카메라 및
손목 카메라를 사용한다. 고정 카메라 시야·캘리브레이션과 실제 끝단 도달 범위를 먼저 검증한다.
바구니 중심은 베이스에서 좌우 31cm이며, 테두리 높이는 12.3cm다.
중심 좌표에 닿는다는 것만으로 충돌 없는 진입/퇴출이 가능하다고 판단하지 않는다.

## 시연 규격

가능하면 같은 OMX 모델의 리더 팔로 추종 시연을 기록한다.
손으로 토크가 꺼진 팔을 움직여 기록한 엔코더는 그대로 목표 명령 시연이 되지 않는다.
관측과 실제 추종기에 보낸 목표 명령을 같은 시간축으로 기록해야 한다.
실물 기록 전 토크/중력 보상·보정·관절 제한을 제조사 제어 방식에 맞춰 준비한다.

LeRobot v3 로컬 데이터셋, 30Hz 동기화 기준:

| 키 | 내용 |
|---|---|
| `observation.state` | 팔 5관절 + 그리퍼 현재 위치, 6차원 |
| `action` | 팔 5관절 + 그리퍼 목표 위치, 6차원 |
| `observation.images.front` | 카트·좌우 바구니 고정 RGB 영상 |
| `observation.images.wrist` | 손목 RGB 영상, front와 같은 해상도 |
| `observation.environment_state` | 목표 물체 중심 u,v (0~1), 좌 바구니 one-hot, 우 바구니 one-hot, 위치 관측 유효값: 5차원 |

물체 중심은 매 프레임 갱신한다. 가려짐은 유효값 0으로 표현하고 실행기는 유효 관측 회복을 확인한다.
한 시연에는 한 개의 지정 상품을 한 바구니로 옮기고 안전 대기로 복귀하는 전체 동작을 기록한다.
SKU·물체 ID·도킹 오차·주문 ID·성공 여부·기록 세션은 별도 에피소드 메타데이터로 보관한다.
학습 입력 목표값은 추론 때도 같은 의미와 정규화로 공급해야 한다. 텍스트 task 이름만 달리하는 것으로
현재 LeRobot ACT가 목표 바구니를 구분하도록 학습되지는 않는다.

단위와 관절 순서를 명시하고 기록/추론을 일치시킨다. 기존 LeRobot OMX 데이터는
약 ±100 범위 정규화 위치일 수 있으므로 ROS 라디안으로 그대로 발행하지 않는다.
그리퍼 변환은 팔 관절 변환과 따로 실제 보정값을 확인한다.

초기 수집 계획은 9종×좌우 2곳×20회=360개 성공 시연이다. 이는 시작 예산이며 충분성을 보장하지 않는다.
먼저 OMX2 상품 한 종으로 양쪽 바구니 각각 20회 수집해 전체 파이프라인을 검증한다.
이후 9종, 카트 위치, 도킹 편차, 주변 상품 0~3개, 집기 자세와 조명을 다양화한다.
주문 조합을 모두 외우게 하는 대신 단일 상품 동작의 주변 조건을 다양화한다.
실패한 행동을 성공 시연으로 섞지 않는다. 실패 복구는 명시적 복구 시연으로 추가한다.

## 학습과 평가

ACT는 현재 관측으로 향후 30프레임(1초)의 명령을 예측하고, 우선 5프레임만 실행한 뒤
재관측하는 설정으로 시작한다. 제어기 지연과 PC의 추론 시간을 측정해 길이를 조정한다.
지연 때문에 관측이 낡거나 명령 공급이 끊기면 그 설정으로 실물 실행하지 않는다.
학습률 1e-5, batch 8, 50,000 step은 초기 탐색 설정이며 최적값은 아니다.

기록 세션/도킹 배치별로 train/validation/test를 80/10/10으로 분리한다.
같은 영상의 인접 프레임을 무작위 분리하지 않는다. 아래 실행 도구는 자동 분할이나 검증 손실 계산을
구현하지 않으므로 학습용 로컬 데이터셋을 별도로 준비해야 한다.
먼저 한 종 실험 → 9종 실험 → 1~4개 주문과 중복 SKU를 포함한 순차 인계 평가를 수행한다.
평가 지표는 상품별 집기·올바른 바구니 투입 성공률, 주문 전체 성공률, 오투입·낙하·충돌 횟수,
평균/최악 처리 시간이다. 손실 감소만으로 성공이라 보고하지 않는다.
단일 상품 성공률이 95%여도 독립 실패 가정에서 4개 주문 성공률은 약 81.5%다.
낮은 성공률의 SKU·도킹 조건을 찾아 추가 시연하고 재학습한다.

## 현재 PC에서 확인된 사항

- `/home/noma/venv/il/bin/python`: PyTorch 2.10.0+cu128, 로컬 LeRobot 사용 가능.
- NVIDIA 드라이버와 통신 실패, `torch.cuda.is_available()`은 False. CPU 학습은 가능하지만 속도 확인 필요.
- 기존 `cygnusx304/pick_and_place`: OMX follower, 30회, 17,817프레임, 30Hz,
  작업명 `Pick up Doll`. 인계 목표 입력과 OMX3 9종/바구니 시연임을 확인할 자료가 없다.
- 현재 상품 위치 표시 모델은 물리적 집기/낙하 학습용 환경이 아니다.
- 실물 OMX3 제어·도킹 인계·손목 영상 수집·9종 상품 정보·이 작업 시연이 준비되지 않았다.

따라서 기존 데이터를 임의로 OMX3 인계 시연으로 간주하여 학습하지 않았다.
사용자 확정: 실물 OMX3의 시연을 수집해 정책을 학습하고 실물 OMX3 상태를 Gazebo와 동기화한다.
추가 확정: 시연 수집과 학습은 다른 PC에서 수행한다. 현재 PC는 그 PC로부터
실물 상태 데이터를 받아 관제와 Gazebo 동기화를 담당한다. 현재 PC에서 학습을 시작하지 않는다.
학습 PC의 GPU/LeRobot 상태는 별도 확인 대상이며, 위의 GPU 점검 결과는 현재 PC에만 해당한다.
실물 OMX3 담당 PC가 제어기와 USB를 소유하고, 학습된 정책의 명령도 이 제어기로 전달한다.
Gazebo는 실제 측정 관절값을 받아 표시하며 정책 명령을 실물로 되돌려 보내지 않는다.
Gazebo 동기화는 물리적 집기 성공 검증을 대신하지 않는다. 상품 인계 판정은 실제 영상 등으로 확인한다.
현재 OMX2용 읽기 전용 관찰 구조를 OMX3에 적용하려면 실제 관절 토픽과 보정부터 확인해야 한다.

구현한 관제 인터페이스(상대 PC 실행기 연동 전): 관제에서 인계 요청 ID·핑키 ID·상품 목록을 보내고,
OMX3 측에서 접수/진행/완료/실패 및 측정 관절 상태를 돌려준다.
관절 상태는 타임스탬프·관절 이름·보정된 위치를 포함한다. 라디안 팔 관절과 그리퍼의 단위를
실물 드라이버/제조사 URDF에 맞추고 LeRobot 정규화 action을 그대로 Gazebo에 보내지 않는다.
상품 표시까지 동기화하려면 별도로 실측 상품 위치·부착/투입 상태가 필요하다.
관절 상태만 받는 구성에서 상품도 자동 동기화된다고 간주하지 않는다.

실행 준비 도구(로봇 제어/외부 업로드 없음):

```bash
/home/noma/venv/il/bin/python scripts/train_omx3_act.py \
  --dataset-root datasets/omx3_handover_train
# 규격 확인, 영상 재생 확인, 단위/시연 검토 후 실제 학습:
/home/noma/venv/il/bin/python scripts/train_omx3_act.py \
  --dataset-root datasets/omx3_handover_train --device cuda --run
# GPU 복구 전 파이프라인 시험은 --device cpu --steps 10 --batch-size 1 사용 가능.
```

도구는 입력 키·차원과 로컬 프레임 파일만 검사하며 시연 내용, 실제 영상 디코딩,
품질, 충돌, 배치 편향을 인증하지 않는다. 현재 기본 경로에는 데이터가 없어 학습을 시작하지 않는다.

근거: [ACT 원 논문](https://arxiv.org/abs/2304.13705),
[LeRobot ACT](https://huggingface.co/docs/lerobot/act),
[Diffusion Policy 원 프로젝트](https://diffusion-policy.cs.columbia.edu/).
ACT를 먼저 쓰는 것은 현재 설치된 OMX/LeRobot 환경과 제한된 작업을 고려한 공학적 선택이며,
Diffusion Policy보다 항상 우수하다는 의미는 아니다.
